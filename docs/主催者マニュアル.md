# SparkPlug ⚡ 主催者（ホスト）マニュアル

イベントを **作る → 会場を仕込む → 本番を回す → 振り返る** までの、主催者向け操作ガイド。
発表者・参加者向けの説明は最小限に留め、**主催者が何を押せばよいか**に絞っています。

> このアプリの前提：サーバーはデータをメモリ上に持つ運用です（軽さ優先）。
> **イベントのログはサーバーが縮む／落ちると消えます。終了時のCSVダウンロードが唯一のセーブ**です（→ [8. イベント終了時](#8-イベント終了時-必ずやること)）。

---

## 0. 用意するもの

| 役割 | 端末 | 開く画面 |
|---|---|---|
| **主催者（あなた）** | 手元のPC or タブレット | **ホスト画面**（手元の操作卓） |
| **会場スクリーン** | 会場PC＋プロジェクター | **会場スクリーン**（みんなで見る演出画面） |
| **発表者** | 登壇者のスマホ | 発表者ビュー |
| **参加者** | 各自のスマホ | 参加者ビュー（QRで入る） |

- 主催者の**ホスト画面**と会場の**スクリーン**は**別の画面**です（1人で両方開いてもOK）。
- ネット環境：参加者はスマホの回線 or 会場Wi-Fiで公開URLにアクセスします。

---

## 1. イベントを作る

1. 公開URL（`https://<あなたのSparkPlug>/`）のトップページを開く。
2. 「**✨ イベントを作る**」にイベント名（例：`PLUG Meetup #12`）を入れて「**作成する**」。
3. 自動で **6文字の短縮ID** が発行され、そのまま**ホスト画面に移動**します（URLに権限トークン `?t=…` が付いた状態）。

> **⚠️ このホスト画面のURLを必ず控えておく**（ブックマーク推奨）。
> ホスト画面は乗っ取り防止のため**権限トークン付きURL**でしか開けません。URLを閉じて無くすと入り直せません。
> 無くした場合は運用者側で `npm run host-link -- <イベントID>`（`HOST_SECRET` が必要）で再発行します。

---

## 2. 4つの画面と、誰にどのURLを渡すか

ホスト画面の上部「**🔗 共有**」セクションに、配るべきURLとQRがまとまっています。

| 渡す相手 | URL | トークン |
|---|---|---|
| **参加者** | `参加者URL`（QRと同じ） | 不要 |
| **発表者** | `発表者URL`（登壇者に渡す） | 必要（自動で付与済み） |
| 会場スクリーン | `/e/<ID>/screen` を会場PCで開く | 不要 |
| OBSオーバーレイ | `/e/<ID>/overlay` をOBSのBrowser Sourceで開く | 不要 |

- 「**コピー**」ボタンでクリップボードにコピーできます。
- 参加者URLは会場スクリーンにもQRで出せる（→ [4. 会場スクリーンのセットアップ](#4-会場スクリーンのセットアップ)）ので、**基本は「スクリーンのQRを読んで」で十分**です。

## 3. 【重要】本番前のウォームアップ

サーバーはコスト節約のため、**しばらくアクセスが無いと眠ります**（scale-to-zero）。眠った状態への初回アクセスは**数秒待たされます**（コールドスタート）。

- **開始5〜10分前に、一度公開URLを開いてサーバーを起こしておく**。
- 大きなイベントや「もたつきを絶対に見せたくない」場合は、運用者側で**当日だけ min replica を 1 に上げて**常時起動にできます。

## 4. 会場スクリーンのセットアップ

会場PC（プロジェクターに映すPC）で行う仕込みです。

1. 会場PCのブラウザで **会場スクリーンURL**（`/e/<ID>/screen`）を開く。
   - **画面共有を使うなら、`https`（公開URL）か `localhost` で開くこと**。それ以外だと画面共有ボタンがエラーになります。
2. **左下「🔊 音を有効にする」を1回クリック**。
   - ブラウザの仕様上、効果音は**このスクリーン画面上で一度クリック等をしないと鳴りません**。開始前に必ず押す。
   - （画面共有ボタンなど、他のボタンを押しても自動で解除されます。保険としてボタンを残しています。）
3. スライドを演出の背景に重ねたい場合は、左下「**🖥️ 画面を共有**」→ 共有したいウィンドウ/画面を選ぶ。
   - コメントやリアクションはスライドの**上に重なって**流れます。
   - 止めるときは「**⏹ 共有を終了**」（またはブラウザの共有停止）。
4. 右下に「**📱 スマホで参加**」QRが出ます（表示ON/OFFはホスト画面から。→ [6](#6-本番中の操作スクリーン設定)）。
5. プロジェクターに全画面表示（ブラウザを F11 等で全画面に）。

> Teamsなどでリモート参加者にも見せる場合は、**この会場スクリーンのウィンドウをTeamsで画面共有**すればOK。
> ただしリモート勢が「参加（リアクション/コメント/投票/質問）」するには、各自のスマホ/PCで**参加者URLを開く**必要があります。

### 4-1. ハイブリッド開催（Teamsでリモート参加あり）の構成パターン

> **⚠️ Teamsで同時に画面共有できるのは1人だけ**です。誰かが共有を始めると、それまでの共有は止まります。

**パターンA：登壇者が会場にいる（基本・OBS不要）**

従来どおりです。会場スクリーンの「**🖥️ 画面を共有**」でスライドを背景に敷き、そのブラウザウィンドウをTeamsで画面共有すれば、会場もリモートも演出付きで見られます（→ 4章本文）。

**パターンB：登壇者がリモート（これもOBS不要）**

1. リモート登壇者はTeamsで普通にスライドを共有する（**スライド操作は登壇者本人のまま**）。
2. 会場PCで `/e/<ID>/screen` を開き、「**🖥️ 画面を共有**」で**Teams会議ウィンドウ**（リモートの共有が映っているウィンドウ）を選ぶ。Teams側で共有コンテンツを全画面表示にしておくと会議UIの映り込みが減る。
3. プロジェクターにこのスクリーンビューを映す → 会場は「リモートの共有画面＋演出」を見られる。

> リモート視聴者がTeams上で見るのは素の共有画面（演出なし）です。共有スロットは登壇者が使っているため、会場から演出付き映像を画面共有で送り返すことはできません。

応用ワザ：登壇者本人に `/e/<ID>/screen` を開いてもらい、自分のスライドを背景キャプチャ→**そのブラウザウィンドウをTeamsで共有**してもらうと、共有スロット1つで会場もリモート視聴者も演出付きで見られます（会場はTeams画面をそのまま投影）。登壇者の協力が必要な上級ワザです。

**パターンC：OBSを使う（必要なときだけ）**

次のいずれかが必要なときに、OBS＋オーバーレイビューの出番です。

| 必要なこと | 理由 |
|---|---|
| Teams会議UIのクロップ | キャプチャしたTeamsウィンドウの会議UI（ツールバー等）を切り取ってきれいに合成したい |
| リモート視聴者にも演出を見せる | 登壇者の共有を保ったまま、OBSの合成映像を**仮想カメラ**として会場PCのカメラに載せる（画質は画面共有より落ちる） |
| 本配信 | YouTube Live等への配信に演出を載せたい |

手順：

1. OBSでスライド/Teams受信画面をソースとして追加する。
2. その上に **Browser Source** を追加し、URLに `https://<あなたのSparkPlug>/e/<ID>/overlay` を入れる。
3. Browser Sourceの幅・高さを配信キャンバスと同じにする（例：1920×1080）。
4. OBSのプレビューでリアクションが透明背景のまま重なることを確認する。
5. 出力先に応じて、OBSの仮想カメラ（Teams還流）、全画面プロジェクター（会場投影）、または配信開始（YouTube等）を選ぶ。

演出を絞る場合はURLクエリを使えます。例：リアクションだけにするなら `?comments=0&questions=0&poll=0&se=0` を付けます。接続確認用の小さな表示が必要なときだけ `?debug=1` を付けます。

#### 仮想カメラでリモート視聴者に見せる場合の追加手順

登壇者の画面共有を止めずに、リモート視聴者全員へ演出付き映像を届けたいときの経路です。

1. OBSの「**設定 → 出力**」または右下の「**仮想カメラ開始**」で、合成映像を仮想カメラとして有効にする。
2. 会場PCのTeamsで、カメラの選択を **「OBS Virtual Camera」** に切り替える（会議中でも設定からいつでも変更可）。これで会場PCの「顔映像」の代わりに演出付き合成映像がTeamsに流れる。
3. このままでは視聴者の画面には**参加者一覧の中の1タイルとして**表示されるだけです。目立たせるには、主催者・共同主催者が **「スポットライト」** を実行します。
   - **ピン留め** は各視聴者が個人でできる操作で、**自分の画面にしか効きません**。「見てね」と口頭で頼んでも強制力はない。
   - **スポットライト** は主催者・共同主催者だけが使える操作で、**会議参加者全員の画面に強制的に固定表示**されます（最大7人まで同時指定可）。実質的にはこちらを使わないと「全員に見せる」目的は達成できません。
   - スポットライト操作は、会場PCの映像タイルを右クリック（または「その他の操作」）→「スポットライト」で行う。運営アカウントが主催者・共同主催者権限を持っていることが前提。
4. 質疑応答などで登壇者本人の顔を映したい場面では、都度スポットライトを解除・切り替える。

トレードオフ：Teamsのカメラ映像は画面共有より解像度・ビットレートが低く、細かい文字は視聴者側で潰れやすい。経路が一往復増える（登壇者→Teams→会場PC→OBS→仮想カメラ→Teams→視聴者）ため数秒の遅延も乗る。登壇者に負担をかけたくない場合の代替手段として割り切って使う。

## 5. 参加者を入れる

- 会場：スクリーン右下の**QRをスマホで読む**だけ。
- リモート/事前告知：**参加者URL**をチャットやスライドで共有。
- 参加者は名前を付けても匿名でもOK（参加者側で選べます）。
- 「🟢 N人が参加中」の人数は、ホスト画面ヘッダーと会場スクリーンに出ます。

---

## 6. 本番中の操作（スクリーン設定）

ホスト画面の「**📺 スクリーン設定**」の3つのトグルで、会場スクリーンの見た目を手元から切り替えられます（**緑＝ON**）。

| ボタン | 役割 |
|---|---|
| **📱 QR表示中 / 非表示** | 会場スクリーン右下の参加用QRを出す/隠す（既定：表示）。全員入り終わったら隠すとスッキリ。 |
| **🔊 効果音ON / 🔇 OFF** | 効果音のミュート切替（既定：ON）。※先に [4-2](#4-会場スクリーンのセットアップ) の「音を有効にする」を押しておくこと。 |
| **💬 コメント：横流れ / 下から上** | 流れるコメントの向き（既定：横流れ＝某動画配信サイトリスペクト）。 |

## 7. 本番中の操作（アンケート・質問）

### アンケート（📊）

事前に**下書きを何個でも仕込んでおき、好きなタイミングで開始**できます。

1. 「**📊 アンケートを作る**」で設問＋選択肢（2〜6個）を入れて「**＋ 下書きに追加**」。
2. 下の一覧「**📝 下書き**」から、出したいタイミングで「**▶ 開始**」。
   - 開始すると会場スクリーン右上に集計パネルが出て、投票がリアルタイムに反映されます。
   - **別のアンケートを開始すると、実施中のものは自動で締め切られます**（同時に出るのは1つ）。
3. 「**🔴 実施中**」の「**⏹ 締め切る**」で終了。締め切ると参加者側の投票UIは消え、スクリーンの結果は数秒後にフェードアウトします。
4. 締め切ったものは「**⏹ 締切済み**」に最終結果として残ります（CSVにも記録）。

### 質問トリアージ（❓）

参加者が「質問として送信」した投稿は、ホスト画面下部「**❓ 質問**」に一覧されます（参加者は👍で応援でき、「後で」はいいね順に並びます）。各質問を振り分け：

| ボタン | 効果 |
|---|---|
| **🎤 今答える** | 会場スクリーン下部中央に「🎤 いま答えている質問」としてピン留め表示。 |
| **⏳ 後で** | 後回しリストへ（いいね順）。 |
| **📮 後日** | 後日回答へ。CSVに残るので、後でメール等でフォロー可能。 |

## 8. イベント終了時（必ずやること）

> ### ★ CSVを必ずダウンロードする
> ホスト画面ヘッダーの「**📥 ログCSV**」を押して保存する。
> 参加ログ・リアクション・コメント・効果音・アンケート・投票・質問（と振り分け）がすべて時系列で入った、**唯一のセーブデータ**です。
> サーバーが縮む/再起動すると中身は消えるため、**閉じる前に必ず回収**してください（Excelでそのまま開けるUTF-8 BOM付きCSV）。

- 画面共有していたら「⏹ 共有を終了」。
- 会場スクリーン・ホスト画面のタブを閉じて終了。

### 振り返り（AIまとめ）

専用のAI分析機能は積んでいません。**ダウンロードしたCSVを Claude / ChatGPT 等に貼って**「盛り上がりのピーク」「よく出たキーワード」「未回答の質問」などを聞くのが想定運用です。

## 9. 困ったとき（FAQ）

| 症状 | 対処 |
|---|---|
| **最初のアクセスが遅い** | コールドスタートです。数秒待つ。事前ウォームアップ（→ [3](#3-重要本番前のウォームアップ)）で回避。 |
| **効果音が鳴らない** | 会場スクリーンで「🔊 音を有効にする」を押したか確認。押した上でホストの「効果音ON」になっているか。 |
| **画面共有ボタンがエラー** | スクリーンを `https`(公開URL) か `localhost` で開いているか確認。 |
| **スクリーンのQRがスマホで読めない** | 参加者URLが会場LAN内アドレスになっていないか。公開URL運用なら問題なし。 |
| **「アクセスが拒否されました」画面** | ホスト/発表者URLの**権限トークン（?t=…）が欠けている/誤っている**。正しい共有URLを開き直す。 |
| **ホスト画面のURLを無くした** | 運用者側で `npm run host-link -- <ID>`（`HOST_SECRET` 必須）で再発行。 |
| **途中でサーバーが落ちた/再接続した** | 各画面は自動で再接続し、同じイベントに復帰します。ただし**その時点までのログ・進行中のアンケート/質問はリセット**されます（頻度は低め）。 |
